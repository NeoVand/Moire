# Moire — agent memory

Canvas-first WebGPU moiré tool. Vite + React + TypeScript + Three.js TSL. Do not edit the rewrite plan file.

## Product contract

- Full-bleed canvas. One studio chrome on the left (Moiré ring mark, view, layers, fields, projects, capture). `I` collapses it to a Moire pill. `E` exports a PNG.
- World Y is up. Flip Y only in `src/gpu/camera.ts` (pointer / zoom-to-cursor).
- Drag moves the selected layer (screen-space; invert layer rotation onto position). Option-drag rotates around the world origin (degrees in UI). Space or middle-drag pans. Wheel zooms to cursor. Shift on sliders is fine control.
- `rotation` is degrees. `rotationOffset` is radians, always present on the layer.
- No `maxRings`, JSON import/export theater, or fake blend modes.
- Tilings (`src/gpu/tilings.ts`) are the lattice family generalized: a tiling is a translation cell plus the polygons packed in it, and the ink is the union of those polygon boundaries — most famous tilings are "pack one shape and the gaps become the others" (hexagons touching at corners leave triangles = kagome; octagons on a square lattice leave squares = 4.8.8). Lengths are in EDGE units and `spacing` is the edge length in world units, so swapping tilings keeps the scale of the drawing. Edges are the unit-distance pairs of the VERTEX set, not the boundaries of the packed polygons: in the snub tilings two triangles meet along an edge that bounds no packed face (nine of the fifteen per cell in 3.3.3.3.6, and the whole triangle row in 3.3.3.4.4), and a face-based edge set omits them while still looking entirely plausible. The catalogue expands once into a BINNED table (`tilingTable`): the cell is divided into `bins × bins` in generator coordinates, and each bin carries the segments and vertices within `BIN_REACH` (0.62 edge units) of it, stored outright so the shader reads them with no indirection. A point folds into the cell, picks its bin, and walks only that — exact below the reach and saturating above it, which is all the ink asks (a stroke, a vertex disk, and a fill inset are each a fraction of an edge). Walking the whole list instead cost 146 ms/Mpx for two enveloped tilings against 40 binned, because the envelope re-walks it every one of 24 taps per layer. The loops are also gated on `drawEdges`/`vertexSize`, so an unused one costs nothing; CPU mirror (`tilingHits`) and GPU read the SAME table, so they cannot drift. The table is static and lives in `uniformArray`s, so choosing a tiling moves a start and a count in one slot — no pipeline rebuild, which is what makes a gallery clickable. `tilingInkFn` must stay a TSL `Fn`: as inlined nodes its dynamic `Loop` nested inside the tap `Loop` lost its scope and the ink froze at one tap (correct at sweep 0, shattered at any sweep). Catalogue entries are checked as tilings, not eyeballed — unit edges, zero polygon overlap, exact area accounting against the declared gaps, periodicity under both generators, ink density matching the largest face's incircle, and — the sharpest one — every vertex having exactly as many edges as its configuration has faces, which is local so no cell-counting boundary can fudge it (`tilings.test.ts`; the area test caught a snub-square cell of 1+√3 where the truth is √(2+√3), and the degree test caught the missing snub/elongated edges). A tiling's cell carries genuine 2D structure where a grid's is a product of two line families, so its envelope wants more taps than a grid's — residue falls as 1/√taps, and Quality raises it.
- `tileFill` inks a lattice's faces inward from their edges: a face fills only once its incircle clears the inset, so one slider sweeps from the largest faces alone through to solid. It costs nothing — it reuses the edge distance already computed — and it applies to the closed-form grids too (`fillReach` gives each type the deepest inset its solver can be trusted to). This is what makes the tilings worth having: with hairline edges the ink coverage is a few percent and the moiré is dominated by the CELL, which is a triangular or square lattice for nearly all of them, so every pair beats into the same fringe system. Filling makes the decoration the signal, and a kagome pair, an octagon pair, and a dodecagon pair then read as three different pictures rather than one.
- V1 patterns: parallel lines and radial lines through the origin; concentric circles, squares, triangles, n-gons; square / hex / triangle lattices (no offset; vertices + optional edges; X/Y scale); curves — wave, parabola, hyperbola, Archimedean spiral, LOG SPIRAL (`curve-log`, type code 13; tiling moved to 14 and its "is a tiling" gates test > 13.5; curve kinds stay contiguous `type − 9` = 0–4). The log spiral is ψ = 32·ln r − bθ: bend 0 IS geometrically spaced rings (radius ×e^{s/32} per member), arms M = round(|B|/s) like the Archimedean, added because §3.2's carrier classification named the dilation and loxodromic clocks as the two group carriers the catalog lacked. BOTH spirals carry the pitch's SIGN as handedness (b = sign(B)·Ms/2π; both twins once collapsed it through abs — counter-spiral pairs, which beat in M_A+M_B rays instead of M_A−M_B, were unreachable and no golden could see it since the twins agreed; mirror identity ψ(x,y;B)=ψ(x,−y;−B) is now a unit test, the Spiral pitch slider goes negative, and teaser panel 3 / the counter-spirals preset now genuinely counter-rotate). A log spiral is a group orbit of the loxodromic flow, so it is IMMUNE to rotation and (nearly) to detune — both act as phase shifts; the plate perturbs it by MIRROR, and its supplemental cell shows the scale-free 2M-lens rosette. Hex edges are hexagon sides, not 3-line families. The catalogue holds all ELEVEN uniform tilings (3 regular + 8 Archimedean). Studio groups them as Lines, Concentric, Tiling, Curves — the `grid` family keeps its id and holds the three regular lattices plus `tiling-periodic`, since the grids ARE three tilings. The paper count is FOURTEEN families / TEN closed forms; numbers.mjs guards the catalog list and fails if the Studio and prose disagree.
- Radial lines: N undirected lines through the layer origin, equally spaced over π. No spacing, progressive, or offset — `lineCount` instead (default 8, max 360). `phase` is Start: a hole of that radius around the origin (0 draws through the center). Type code 8.

- Pattern colors are the only accent. Background default is `#ffffff`.
- Hugeicons only. Lines use `Asterisk02Icon`, not `EqualSignIcon` or `LineIcon`.

## Inverse math (CPU and WGSL must stay twins)

Ring `n`: shape of radius `n * spacing + phase`, center `rotate(n * δ, n * θ)`, then `q = rotate(p - center, -n * θ)`.

- Centered (`δ = 0`, `θ = 0`): `mod` of `shapeRadius`.
- Circles + translation: conditioned quadratic, then neighbor integers.
- Squares + translation: closed-form L∞ axis candidates.
- Rotation, or translated polygons: Newton plus a sweep of `n` over `[nMin, nMax]`. Rotation fans the nearest index away from `|p|/spacing`; missing that range drops whole sides (the “broken segments / white holes” when zoomed out).
- Rotation past the fold radius ≈ `spacing/θ` makes `h(n)` non-monotonic: several BRANCHES of the family pass every point, and the members adjacent in residual have indices far from `n`. The scan therefore tracks its two runners-up (`ScanHit`, `vec4(h, n, alt2, alt3)`), the skip bar protects the third-nearest when the phase is measured, and the trio slots take the residual-adjacent branches over the index neighbours. Callers that consume the phase (envelope/ratio/contours — `needPhase` in `solveLayers`) must pass `acceptBelow = 0`: the early exit hands back a merely-close member, the true neighbours then measure NEARER, get rejected, and the gap falls back to nominal spacing — the envelope averages the wrong period and the carrier survives as sector hash (the hexrot bug; zoo case `hexrot-spiral-envelope`, crowded-ring block in inverseCpu.test.ts).
- `shapeRadius`: `length` (circles), `max(|x|,|y|)` (squares), regular-polygon radial metric (tri / n-gon).
- Three.js `wgslFn` only parses the first `fn` in a string. One helper per `wgslFn`, passed as includes.
- Parallel lines: `mod` of the projection. Radial lines: `max(r * |sin(wrapToHalf(atan2(p), π/N))|, start - r)`.
- Curves: type codes 9–12. No walking offset.
  - Wave: `φ = x − A sin(2π f y / 32 + ψ)`. `bend` is A, `frequency` is f (1 = one cycle / 32), `phase` is ψ. Ink `periodicDist(φ, spacing)`.
  - Parabola: one upward family `y = 0.01 B x² + n s + phase`. Bend 0 is horizontal parallels. Euclidean band `periodicDist(ψ, s) / |∇ψ|` (sides darken at high bend).
  - Hyperbola: rectangular `√|x² − y²| = n s + phase` for n ≥ 1 (east-west and north-south). No quadratic wrap.
  - Spiral: Archimedean. Spacing is the arm gap. Starts `M = max(1, round(B / s))`, used pitch `M s` so the cut stays closed. `periodicDist(r − (M s / 2π) θ − phase, s)`. Pitch 0 is concentric.
- The concentric phase is two WGSL halves, `ringHit` → `ringTrio`, twin of the one `ringPhaseCpu` (whose sample now also carries `n`): the split exists so the nearest member's index reaches `ringIndexDir`, the closed-form index direction of every concentric family — walking and rotating ones included, where it is that member's facet normal rotated by nθ. `ringIndexDirCpu` is its twin and the test pins it to a finite difference of the residual.
- Files: `src/gpu/inverseCpu.ts` and `src/gpu/inverse.wgsl.ts`. Tests: `node --experimental-strip-types src/gpu/inverseCpu.test.ts`.

## Fields

A field is a displacement of a layer's *index*: `shift` many members, wherever you stand. Every family spends it in its own currency — phase for the level-set families, a rotation for the radial fan, a translation along the first generator for lattices — so the fringes against an unmodulated twin are the level sets of the field.

- `src/fields/expr.ts` parses `f(x, y)` to stack bytecode. Guards (`EXPR_EPS`), opcodes and limits live there and are shared, so no evaluator can drift on numbering or on where a singularity is clamped.
- `src/fields/emit.ts` unrolls that bytecode into **straight-line code**: no loop, no dispatch, no stack, nothing passed in. It is backend-agnostic; `wgslBackend` ships and the JS backend in the test exists so the unrolling can be checked against the interpreter without a browser. Do not put an interpreter back in the shader — that was 50 ms a frame, and nearly as much for an *empty* program, because the call had to hand the program over first.
- `src/fields/evalExpr.ts` is the CPU twin (dual numbers, forward-mode AD), used by the editor's preview and the paper's CPU mirror.
- Chain rule: a term with an exactly-zero factor contributes nothing, even against an overflowed partial. `evalExpr.ts` does that in `term`; `emit.ts` folds the same zeros while generating code. A plain multiply gives `0 · ∞ = NaN` and poisons the gradient.
- One generated `fn moireField{slot}` per layer that carries a field, so **a new expression is a new material**. `MoireRenderer` debounces that on `FIELD_SETTLE_MS` (220 ms) and holds the last frame across the build. Amount and extent are uniforms and never rebuild.
- Tests: `node --experimental-strip-types src/fields/expr.test.ts`.
- AN IMAGE IS A FIELD (`FieldSpec.image`, a data URL of a small greyscale PNG the field editor makes from any picked picture, 512 px on the long side): the index shifts by `amount` times the image's darkness, read in layer coordinates over a box `scale` world units wide with the image's own aspect, zero outside, and the expression is ignored while an image is set. In the shader it is one `texture()` read at level zero plus two central differences for the gradient (`isImageField` branch in `solveLayers`); the renderer decodes the image before the material that samples it is built (`loadImageFields`, keyed by `fieldSource`, which hashes the data URL into `image:<len>:<fnv>` so a new picture is a new material exactly as a new expression is). This is the INVERSE MOIRÉ of paper 3: duplicate a layer, give the copy the image at amount one half, and in register the overlay shows the picture; a quarter-pitch shift shows it embossed, a larger shift shows it as a negative, a small rotation carries it on the bands. The shader reports NO gradient for an image field, on purpose: the stroke is a Euclidean band divided by the index gradient, so a reported warp turns a wander of lines into a wander of pen widths and the interleave covers 75% here and 100% there; at zero gradient the band is measured in the family's phase, every member keeps its duty, and a keyed pair goes solid in register (the rate machinery reads such a layer at its nominal rate). A PICTURE SITS ON ONE LAYER OR TWO (`FieldSpec.mode`, a uniform, so switching never rebuilds): `plain` shifts this layer by the picture; `halves` gives two layers half the shift each in opposite directions (`role` ±1) -- the theory's optimum, since a crisp overlay needs the difference to jump by one half at every edge and a quarter each is the least either layer can jump -- and the studio sets `soften` so the quarter bends over half a pitch (a mip level converted through the picture's width, `IMAGE_SIDE`), which makes the layers' edges a gentle S and the overlay crisp to half a pitch. `weave` (both layers jittered by half the amount per cell -- one pitch across the members, `cell` pitches along, aligned to parallel lines and concentric rings -- with signs hashed from the cell and `seed`, the role -1 layer flipping whole cells inside the picture with probability equal to the cell's mean darkness) hides the picture from either layer completely, and is SCENE-ONLY: the shader draws it and the paper's generator uses it, but the Share row does not offer it, because the author judged that it costs the layers their look. The partner of a shared picture is the layer with the same image and the opposite role (no id stored); the studio mirrors the shared dials (image, mode, amount, scale, soften, seed, cell, enabled) to it, puts the other half on the unmodulated twin (same type and pitch, no field) or a fresh copy, and Remove clears both. `soften` is a mip level the picture is read at (mipmaps on), the Edges dial; Fill and Outline are amount one half and one. The zoo bridge has `dump()` for reading the construction back. No CPU twin yet, so the paper's CPU mirror does not evaluate image fields.
- A circle-valued field mints DEFECTS: `theta/tau` at integer amount A ends A fringes at the origin (the fork grating; zoo `line-fork-render`/`line-fork-envelope`). The signed count of fringe endings inside any loop is the enclosed charge × amount — quantized, localized, additive, blind to the field's exact part — and the fringe law fails inside the core r* = 2As/π where η crosses 1/4 (`node --experimental-strip-types paper/tools/exp/defects.mjs`, gates exact). A NON-integer amount tears the drawing along the evaluator's branch cut; that tear is real, not a bug — it carries the fractional winding.

## Renderer

- The character scan, the lattice matching, the analytic `*IndexDir` gradients, and the sweep's diagonal twin all sit behind ONE uniform gate (`scanOn` in `buildColorNode`: taps > 1, ratio, or contours). A plain render reads none of their outputs — one tap at zero sweep never consults a rate, and every eta consumer in `grade` is behind a view toggle — but ungated they ran per pixel anyway and TRIPLED the plain render (22 → 66 ms per 2.7 Mpx frame; the gate restored 22 and even sped the envelope/ratio views, 79 → 49 ms). The gate is uniform control flow, so `dFdx/dFdy` must stay OUTSIDE it (WGSL uniformity analysis); the xi extraction and gradient mixes are cheap and stay unconditional. Measure with `tests/zoo/render.mjs` on a probe scenes module at `--scale 3`, repeats per scene, comparing the later repeats.
- INTERACTION RESOLUTION (renderer.ts): the exact envelope costs 60–140 ms per full-size frame at a retina window (6–15 Mpx), the plain render under a vsync even at 15 Mpx, and the app renders on demand at the container's size times min(devicePixelRatio, 2). While a hand is on something — a drag on the stage (`hold()` from the stage's pointer down/up), a slider (the transport's `interacting` flag, subscribed in MoireStage), a wheel burst or a playing animator (requests within `SETTLE_MS` of each other) — frames render at a reduced buffer (`setPixelRatio(dpr · scale)`, the zoom uniform scaled with it so the framing is identical by construction), and a full-size frame follows `SETTLE_MS` after the hand lets go. The envelope is an average over the carrier's period, so its picture holds no carrier-scale detail and survives the downsample; the plain render measures fast and never triggers it. Snapshots and the zoo force scale 1 first, so goldens never see it. PACING: the stream starts from the cold queue time of the last isolated full-size frame (`fullCost`, measured with `queue.onSubmittedWorkDone`; an idle GPU measures ~1.6× cold, so the start is a notch pessimistic), and inside the stream the ONLY reliable verdict is the animation-frame cadence read by a continuous metronome — Chrome throttles requestAnimationFrame under GPU back-pressure and not otherwise, and a continuous loop is independent of how often the mouse moved. Two signals that look right and are not: per-frame queue completion times (Chrome observes completions once per frame, so every frame reads as one vsync at any scale) and the wait between a frame's request and its callback (pointer events are dispatched frame-aligned). Cost goes with the square of the scale, so an overrun window drops straight to the notch that fits and locks it for the stream; two clean windows step up a notch; the frames right after a change drain the old buffer and do not vote; where a stream ended is remembered with the notch that overran, keyed by view flags, layer count and buffer size (the cold measurement varies 3× between runs of the same scene, so it cannot key anything), and the next stream under the same key starts there without re-probing. Nothing is a stream within `WARMUP_MS` of a mount or rebuild: the app's startup burst once registered its own warm-up jank as "full size overruns" and the plain render could never step back up. Measure with `node tests/zoo/drag.mjs [cssW cssH dpr] [--only fan]` (2560 1440 2 is a 5K display): it drags the stage with a mid-drag pause and prints the cadence, the buffer ladder walked, and long tasks. Before this: fan-trio envelope 15–17 fps at 6.4 Mpx and 8–10 fps at 14.7 Mpx; after: 58–60 fps at 0.5 and 0.35 of the buffer, full size 150 ms after release.
- The slot UNIFORMS are a fixed `MAX_LAYERS` (12) array, allocated once and never reallocated — but the MATERIAL is compiled only for the slots a stack actually uses (`slotsNeeded` = layers present, clamped). An inactive slot is not free: its `If(active)` branch still costs registers, and the lattice coordinates every slot contributes are computed in uniform control flow because their screen derivatives cannot live inside a branch. Twelve slots for a two-layer drawing measured **3.8× the per-pixel cost** of two, and specialising took the plain two-ring scene from 19.6 to 0.3 ms/Mpx. Hiding a layer stays a uniform write (`active = 0`) and never rebuilds; changing the layer COUNT or a field expression does. Field edits wait out `FIELD_SETTLE_MS` because they are being typed; a count change rebuilds on the next frame, since a click has already stopped and a new layer must not be invisible for a quarter second.
- THE HANDOVER QUILT, RESOLVED (exhibit `paper/notes/handover-quilt.json`, zoo `walk-field-quilt`): a pair with IDENTICAL nominal spacing and IDENTICAL centres, one carrying a steep dipole field, showed zoom-migrating pockets of carrier-pitch rims in the envelope — hatched wedges, combs, dotted rays. The bisection had cleared the exact integrator, the contrast, the trio and the precision, and convicted the first-order sum handover: right about the mechanism, but the cause sat upstream. Both rings WALK by `offset (−0.07, −0.014)`, a fiftieth of a spacing per member, which put the pair on the walking families' dFdx gradient path, and at the exhibit's 1.87 px per member a screen derivative of the fractional index ALIASES (the unit unwrap needs two pixels per member): the two layers unwrapped differently in angular sectors, their SUM read as the slow character, a first-order winner needs no licence, and the sweep held carrier-pitch rims wherever the wrap flipped — which is why the pockets migrated with zoom. Proof before any fix: the same scene at three times the pixels per member was clean, and so were the walk-free and the zoom-1 variants. The fix is not a licence rule but the closed-form direction for walking families (the nearest member's facet normal in the layer frame, see Inverse math), which retired the dFdx path altogether: the walk-free variant is bit-identical before and after, `rings-sum-handover` and `walk-pair-envelope` matched their goldens, and `hexrot-spiral-envelope` re-blessed by 1.2% of pixels along its fold crescents, where the nearest member jumps between BRANCHES by a non-integer fraction no unit unwrap could repair (at 3× the pixel density old and new agree to 0.03%). The principle, for good: a counting map's gradient is never estimated from the screen — every scalar family's is closed form, and the lattices' dFdx of a LINEAR coordinate is exact, not an estimate.
- THE SQUARE-LAW OBSERVER (`view.envelopeSquare` → uniform `observer`, a ToggleRow under the envelope dials): the observer theorem's N∘I with N the square, applied to the COMPOSITED drawing per tap and per Gauss node BEFORE the average (`mix(c, c·c, obs)` in sweepStack and in `exactChain{K}`'s generated nodes, which take `obs` after `bg`). The pivot follows: E[c²] over independent phases, composed EXACTLY from each layer's (E[α], E[α²]) by `pivotStep` — `exactLayerMean` returns vec2 (mean, mean of the square), the tap loop accumulates `sumLayerSq` — because with c' = c(1−α) + col·α and α independent of c, E[c'²] = E[c²](1−2m+m₂) + 2E[c]·col·(m−m₂) + col²m₂. Squaring doubles the integrand's degree past Gauss-3's five, so exactsweep.mjs certifies the square-law chain on its own: 7.9e-4 worst (a fifth of a gray level), the shipped WGSL within 5e-7 of the twin, per-layer mean squares within 8e-4. Same characters survive, only amplitudes change: a duty-1/2 stroke's station null is EXACT under the linear observer at every zoom (symmetric anti-alias ramps keep half-wave antisymmetry) and reopens under the square-law in proportion to the ramp — zoo `dutynull-linear-envelope` (flat) vs `dutynull-square-envelope` (banded) at zoom 0.25, where the 0.7-px ramp is 2.8 world units of a 16.4 pitch. The sole-layer constant pivot is NOT squared (hard ink is two-valued, E[c²] = E[c]). CPU mirror: `envelope(v, layers, { square: true })`. Linear path bit-identical: `mix(c, c², 0)` is c.
- THE EXACT SWEEP (`view.exactSweep`, raised by writeSlots when the envelope is on and every visible layer — morph sources included, read off slot uniforms — carries a scalar index): the enveloped mean is INTEGRATED IN CLOSED FORM, not tapped. Each layer's swept profile is piecewise cubic in u with corner positions known from the phase trio (nearest member's window; hInk±aa ramps; floor clips; argmin midpoints ONLY when hhi > gap/2; the wrap seam; a SYMMETRIC trio — every closed-form family — emits only the nearest member's corners since the neighbours coincide mod gap, third the events; walking families' asymmetric trios emit all three) — `exactEmit`/`exactChain{K}` (generated WGSL per compiled slot count, one fn serving both schedules via rate args) segment at the corners and integrate Gauss-4 per segment. CERTIFIED by `paper/tools/exp/exactsweep.mjs` (writes data/exactsweep.json; numbers.mjs fails on its gates): 480 scenes across twelve regimes — pairs and trios on the diagonal and on deviated schedules up to the rate-12 station, walking trios, radial floors, sub-pixel strokes, touching strokes — against a 65536-tap double-precision truth; the Gauss-3 chain is within 7.4e-5 (a fiftieth of a gray level), a Gauss-4 pass within 2.3e-8 (every corner is named), and the SHIPPED WGSL, compiled by `paper/tools/gpu/exactsweep.mjs` into a compute pass over the same trios (composite.ts exports `exactSweepWgsl(K)`, the shader's own text), matches the JS twin to 3e-7; 24 taps err by 0.51 at the rate-12 station and the chain beats them 6900-fold at worst — the "annoying envelope artifacts" were tap noise. The pivot is `exactLayerMean` per layer (single-stream, full-period), composited. ARCHITECTURE MATTERS MORE THAN FLOPS HERE: the first cut used a global per-pixel event array (224 f32) + insertion sort — the function-space array spilled to scratch across five live calls and collapsed occupancy to 6× the tap cost. The shipped design stores NOTHING global: each layer's corners fold into ≤20 sorted RESIDUES modulo its own period P = 1/|rate| (`exactResidues`), and a K-way cursor merge streams segments in order — no event list, no sort, no cap, any rate. Gauss-3 (not 4: validated 5e-4 worst, a tenth of a gray level; Gauss-2 fails at 1e-2) and a devW>0.003 gate on the deviation chain finish it: the fan trio runs 89ms at 11.5Mpx vs 115ms for 52 taps — the exact envelope is FASTER than the tap loop it replaced, with zero noise at any zoom, thinness, or rate. Quality dial is a no-op on scalar stacks (Research panel shows "exact"); lattices AND morphing stacks keep the tap loop (a morph carries two trios, the chain one; renderer gates on `hasLayerMorphs()`). Zoo: all 55 goldens matched WITHOUT re-blessing (exact ≈ well-tapped within budget). The torus framing behind it (envelope = conditional expectation over the schedule subtorus; candidate collapse of the paper into 5 laws) is in `paper/notes/torus.md`.
- Envelope view is the continuous-domain mean ink: one pass with `ENVELOPE_TAPS` taps sliding each family through exactly one of its own local periods. Level-set families slide their residual with `phaseDistWgsl` on the `(r, rUp, rDown, floor)` phase sample — no re-solve per tap. Lattices resample instead: one generator advances by `u` coherently and the other by the golden ratio (a rank-1 rule — in lockstep a lattice beats against itself). Which combination rides `u`, and stepped which way, is chosen per pixel among the first three rings of the dual lattice — `(1,0) (0,1) (1,1) (1,−1) (2,1) (1,2)` plus the doubled generators `(2,0) (0,2) (2,2)` — by matching each one's exact index gradient (`local · b_k`, linear, so `dFdx` is exact) against the ranked partner's `gradA`, forward or backward, with a per-kind ink weight multiplying the match error (a honeycomb's wall families are its SECOND dual ring — normals `(1,−1) (2,1) (1,2)`, pitch `(√3/2)s` — so hex weights favor ring two; ring three is the honeycomb's vertex rows and a thin grid's second harmonics; square has no ink at `(2,1)` or `(2,2)`; each schedule is the unimodular completion sending its own combination to `su` and every other candidate to a nonzero mix, so the lattice still never self-hatches — except the doubled combinations, whose bare generator rides `u/2` and half-washes, a carrier-scale residue accepted under the coarse fringe). A global choice erases beats along the unchosen directions or counted the other way (the lattice edition of the sum-moiré convention; a ring partner's counting direction rotates around its centre). The envelope's ranked pair falls back to the topmost eligible layer alone (`envelopePair`) — the ratio view still needs two, but with one grid and one family the partner gradient would otherwise be the zero vector and the choice degrades to noise. Lattice⊗lattice: with no scalar layer visible, `latA` names the topmost lattice as reference (twist mode); every other lattice matches each generator, signed, to the reference's per pixel and rides the SAME `(u, {iγ})` schedule, so both slow characters of a twist pair (a₁−b₁, a₂−b₂) survive the average exactly while carriers, self-beats, and cross-beats scramble away (w = (1, γ, 1, γ) on T⁴). A sole lattice with no partner washes to its own cell mean. With a scalar visible the legacy partner-gradient path runs and lattice⊗lattice beats remain unhandled there. THE DIAGONAL IS THE ENVELOPE; a rate deviation is an exception under four gates multiplied into `devW` (P·R·T·L, each a fade so no seam can form). P — margin against the best zero-sum candidate, scaled ×(1+w)/2 by the winner's amplitude weight (a station embedded in visible zero-sum texture rides the diagonal; zoo `fan-trio-envelope`). R — the winner's weighted merit must sit inside the fringe regime: first-order sum beats keep the tuned hash band (1.7–3.4×thr — retiring rims, zoo `rings-sum-handover`), but higher orders fade from thr to 1.7×thr, at the line where the map itself stops calling them fringes (tighter half-washed the legitimate 5:2 hold, whose 1° rotation prices a perfect lock at ~0.7 thr). T — the tap budget must resolve the schedule: a rate-q slide samples each period taps/q times, gone under ~8 (deep stations die here at default taps; the Quality dial legitimately revives them). L — the LICENSE, the structural one: deviation identity is a decision of the STACK, never of the pixel. `pairLicense` in `writeSlots` runs the 1D convergent merit on each ranked pair's NOMINAL spacings (radial fans certify nothing — member gap grows with r) and licenses at most ONE higher-order character per pair per frame (uniforms `licAB/licAC/licBC`; first-order sums/diffs bypass, keeping the handover behaviour). ## Paper site

The ladder is now a THEOREM, not a taxonomy. §3.2 "Where the rungs come from": every family is a group orbit (four one-parameter similarity flows — translation, rotation, dilation, loxodrome; transverse seeds never fold; winding ⇔ rotational part; the classification names two unshipped carriers, geometric rings and log spirals) or a propagating front. §6.3 "The fold law" (`lem:foldlaw`): a front folds exactly where its support-function normal speed ∂ₙHₙ = s·H(w) − ρₙθH′(w) + ⟨c′(n),û⟩ vanishes (Jacobian −(H+H″)∂ₙH). Corollaries: rotation folds every gauge but the circle at ρ* = s/(θ·sup|H′/H|) — k-gon L = tan(π/k), Euclidean onset R* = s/(θ sin(π/k)) at the vertices; ellipse L = (a²−b²)/2ab, R* = ρ*√((a²+b²)/2); the drift constant m = rad(−δ) is a MACH NUMBER (fold ⇔ m > s; m = s is the sonic locus where the window theorem degenerates and Prop closed's residual goes flat). §6.4: θ=0 makes h_p convex for EVERY gauge (one fact behind mod/quadratic/polygon-prop; translated-ellipse gauge = same quadratic, verified); `prop:untwist` — rational twist 2πa/b splits into b convex classes (closed form of size b, verified exact at 4π/7), and the only mechanism a formula has is freezing frames on finitely many classes (finite ⇔ rational); the interpolated incidence is non-semialgebraic for ANY θ≠0 (cos transcendental over ℝ(ν), definable-center extraction) — Kepler-class, but multivalued: branches through a point grow linearly with radius. Gates in `paper/tools/exp/foldlaw.mjs` (brute nesting/membership tests, no support calculus; onsets within 2.8%, splits exact to 1e-7); figure `foldlaw-figs.mjs` → `fold-law.png` (crimson over brute renders — Mach wake rays trimmed to n≥0 tangencies; for the rotating panels the overlay is the CAUSTIC CURVES ρ(w) = sH/(θH′) mapped through the frame turn — polygons carry a second envelope component, the vertex trajectories, because a support corner absorbs a slope range — plus a dashed onset circle; an onset-circle-only overlay read as unrelated to the visible arms and the user flagged it). Consecutive-member crossings are BORN on the caustic (gated to 0.07 world units) and drift as the lens deepens (Rolle: within the dip depth; gated ≤1.5 gaps) — the deepest-excess point is NOT on the caustic past onset, don't gate that. Above both generators sits the incidence form (§3.2): rungs = branch structure of ν(p) from F(p,ν)=0 — glues (exact) / monodromy (winding) / discriminant ∂νF=0 (fold); fields can add monodromy (defects) but never a discriminant. ## Checks

**`npx tsc --noEmit` checks nothing here.** The root `tsconfig.json` is a solution file — `files: []` and two references — so that command typechecks an empty program and exits 0 no matter what is broken. `npx vite build` is no better: esbuild strips types without reading them. Use what CI uses:

```
npm run build      # tsc -b && vite build -- the actual typecheck
npx eslint src
npm run zoo        # before AND after any change under src/gpu/
```

CI is `.github/workflows/` → Deploy Pages, and it runs `npm run build`. A green `tsc --noEmit` next to a red pipeline means this trap, not a flake.
